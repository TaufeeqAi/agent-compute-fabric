# Contract compliance — the developer platform

How the platform's contract (version 1.1.0) is carried out in this repository: where each rule lives in
the code, which tests hold it, what the implementation adds, and where it falls short. The contract is
the authority; this page is a map of the code, and where the two disagree the code is wrong.

Rule identifiers (`IDM-5`, `SEC-122`, `T3-RED-31`) are the contract's. Paths are relative to the
repository root. `api/` stands for `apps/api/src/acf_api/`, and a test file without a directory is in
`apps/api/tests/`.

Three other pages complete this one: [ARCHITECTURE.md](ARCHITECTURE.md) explains the design,
[DECISIONS.md](DECISIONS.md) records the choices the contract left open, and
[VERIFICATION_STATUS.md](VERIFICATION_STATUS.md) says what was run, with which result, and what was not.

## 3. Where the host does not yet offer what the contract asks of it

The contract asks the execution plane for twelve additive changes and states a fallback for each. The
fallbacks in force:

| Request | Fallback implemented here |
|---|---|
| EP-1: tell a caller its peer id and role | The peer id is taken from the first tagged view and journaled (`pipeline/observation.py`). The role is linted in the host's own table: `acf-api check --host-enrolment`, which the installer's `check` and the deployment test run. |
| EP-2: intent on the snapshot view | A snapshot's intent is read through a sandbox that still carries it; otherwise a restore is refused unless the grant is unrestricted (`pipeline/admission.py::_snapshot_intent`). |
| EP-3: a forgetting floor | A host `NOT_FOUND` proves absence only inside the acceptance horizon; otherwise the answer is `OUTCOME_LOST`. |
| EP-4: create with start as one operation | Not offered. The SDKs and the CLI drive create, then start. |
| EP-5: ceilings per scope inside host admission | The admission lock of a project, and a count read from the host inside it. |
| EP-6: advertise the rate limits | `host_ops_allowance` and `host_reads_allowance` are configured. |
| EP-11: the host's time | A clock offset is noticed only when the host refuses a fresh `issued_at`. |
| EP-7, EP-8, EP-12 | Nothing to build here. EP-9 and EP-10 are not requested. |

One value the contract's requests do not cover is also missing from `host.info`: **what the host admits
at once**. The register's two quota rows default to a share of "the host envelope", and the host
advertises only its pool of identifiers, which is a ceiling of the envelope and can be hundreds of times
larger. The platform therefore takes the envelope from two parameters of its own (section 4, first row).
A request to the execution plane to advertise `envelope.max_sandboxes` and `envelope.max_snapshots`
would remove them.

## 4. What the implementation adds

Nothing here changes a rule of the contract. Each is a choice where the contract was silent, or a check
that is stronger than the one it names. [DECISIONS.md](DECISIONS.md) has the reasoning.

| Addition | Why |
|---|---|
| Parameters `host_max_sandboxes` (16) and `host_max_snapshots` (64), beside the register | The quotas need the host's envelope and the host does not advertise it. Without them a quota was a share of the identifier pool, or not enforced. ADR-125. |
| Parameter `host_connect_timeout` (5 s), beside the register | The one wait of the binding that the register leaves unnamed. |
| The store refuses a journal that ends before the last record the store applied | The chain cannot show records missing at its end. Stronger than "the store exists and the journal does not" (IPS-14). ADR-126. |
| `acf-api compat`, with a file of reviewed exceptions | The contract asks for breaking-change detection (T3-VER-01) and does not say how. ADR-127. |
| `acf-api check --host-enrolment` | The lint the contract names for the platform's role (T3-RED-45). ADR-128. |
| Both configuration schemas read every value exactly | The contract refuses unknown keys (VER-11); a mistyped value is refused as well. ADR-129. |
| `security.allow_shared_identity` admits a shared account and nothing else | Development only; it does not open a secret to an edge account of its own. |
| Exit status 78 for a start that a precondition refuses; readiness is reported to the service manager | So that a unit is not restarted into the same refusal. ADR-120. |
| SDKs: `sandboxes.handle(id)`, `executions.handle(id)` | A handle without a read, so that a cancel is the first request and never waits behind a read. |
| Python SDK and CLI: `ca_file`, `ACF_CA_FILE`, `acf auth login --ca-file` | A platform with a certificate authority of its own is otherwise unreachable, because neither client reads the general certificate variables. |
| CLI: `acf operation list`, `acf auth logout`, `acf auth login --mcp-url`, `acf mcp --profile` | The command-line face of operations the API already has, and the other half of `auth login`. |
| An address with a space, a line break or a character that does not show is refused by both SDKs and the CLI | A URL parser would remove it silently, and the address used would not be the one written. |

## 5. Where the implementation falls short, or reads the contract narrowly

| Rule | State |
|---|---|
| MCP-2, MCP-12: revision 2025-11-25 and the tasks extension, each behind an operator's switch | **Not implemented.** Both switches exist and default to off, as the register requires. Turned on, the adapter refuses to start for the first and the core's configuration is refused for either: a switch that did nothing would be a promise nobody keeps. |
| MCP-13: resources and prompts | Not offered. The contract does not require them. |
| CG-3: one-step create when the host advertises it | Never offered: the host protocol this version speaks has no such operation. ADR-130. |
| HB-11: read the allowance from `host.info` when advertised | Not read. The host advertises none and its field is not defined; the configured values are used. |
| B22: spans of the agent protocol | Emitted by the core, which sees every call, with the conventions' names and the caller's trace context; the adapter emits none. The OpenTelemetry API is an optional extra: without it nothing is emitted. ADR-117. |
| CLI-3: the operating system's credential store when available | Not used. The credential is a file that only its owner can read. |
| B29: a setting for certificate authorities | The TypeScript SDK has none, because the platform's `fetch` takes none. Node's own variable, or a `fetch` of the caller's, is documented. |
| ERR-4 for one host class | An execution whose guest broke the guest protocol ends with the host class `PROTOCOL_ERROR`. The contract's code list has that name only for refusals of the platform's own request, so the failure is shown as `UNRECOGNIZED` with the raw class, as PUB-6 says for a value the mapping does not hold. |
| IPS-13: the audit outbox's budget | Enforced by the engine's page limit on the audit file. The write-ahead log of that file can pass the budget briefly, until its next checkpoint. The reserve of the registry and the ledger is not touched by it. |
| TV3-4, TV3-7: a fault at every point of an exchange | Proven against a model of the host inside the tests. The host's in-memory build offers no way to lose an answer on demand, so against the real protocol only the ordinary paths and the refusals are proven. ADR-122. |
| An edge process stopped by a signal | Ends with that signal's status, as its HTTP server does after a clean shutdown. A service manager counts that as a clean stop. |
| SVC-8 for two reads that reach no host | `whoami` and the listing of agent credentials are answered from the registry before any rate is applied. They are bounded by the edge's connection and in-flight bounds only. |
| AZ-7, in one refusal | When a sandbox view carries no resources, an image without a readable alias is judged by one path as readable and by the other as unreadable. The request is denied either way; the reason and the retry advice of the denial differ. |
| CC3-3 in the containment lane | A stale generation is recognised by comparing a public code with the host's class of the same name. That is correct while the two vocabularies are equal, which the mapping table states for this version (PUB-2). |

## 6. Not built, because the contract defers it

Surfaces the contract names as deferred or out of scope have no route, tool, SDK module or command
here, and no name is reserved for them: workspaces, experiments, evidence bundles, billing, a policy
engine, tenant identity, placement across hosts, streaming output, file transfer and webhooks. The seats
where some of them will attach exist because the contract defines them now: the `Authorizer` port
(`policy/authorizer.py`), the host recorded with every ledger entry, and the audit outbox.

## 7. What is not verified by anything in this repository

Stated once here and in detail in [VERIFICATION_STATUS.md](VERIFICATION_STATUS.md):

* a real host with KVM behind the platform (the levels the contract calls L4 for a real host);
* the workflows on a hosted runner: they are checked statically and their `make` targets run locally;
* a published package, its provenance, and the developer journey from published packages (T3-REL-01,
  T3-REL-02, T3-DX-01 at the release level): the names are not registered;
* an external authorization server: access tokens are verified against keys made in the tests.
